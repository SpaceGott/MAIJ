# Build-Order Decision Matrix

Use this reference when deciding between a **micro-to-macro** (inside-out) or **macro-to-micro** (outside-in) assembly order for a multi-concept Roblox simulation game.

## Definitions

| Approach | Order | Philosophy |
|---|---|---|
| **Micro-to-Macro** | atomic interaction mechanic → regional/job module → formal formulas → full world simulation | Lean/scientific: ship measurable proof points first, each phase earns the next |
| **Macro-to-Micro** | world container → flagship roleplay shell → nested job modules → micro mechanics | Systems-architecture/Roblox-first: build one deep flagship that contains everything |
| **Dual-Track** | blueprint the macro container, build the smallest mechanic first as a testbed, then slot it into the container | Hybrid: macro vision with micro delivery discipline |

## Comparison

| Dimension | Micro-to-Macro | Macro-to-Micro |
|---|---|---|
| **Scope risk** | Low per phase; each phase ships in 4–8 weeks | High; five systems risk half-finished states |
| **Measurement purity** | Clean; one variable isolated per phase | Noisy; confounding gameplay variables |
| **Roblox platform fit** | Three smaller games dilute attention | One deep flagship maximizes retention and algorithm pickup |
| **Data realism** | Laboratory-grade but artificial context | Authentic roleplay context |
| **Time to first published artifact** | 4–8 weeks | 12–20 weeks |
| **Monetization** | Weak (standalone educational games under-monetize on Roblox) | Strong (roleplay economies monetize well) |
| **Pipeline warm-up** | High (small stakes first) | Low (full-scope stakes immediately) |

## Selection Rules

1. Choose **Micro-to-Macro** when the founder's time is constrained (coursework, exams, fellowships) and a published research-grade artifact (e.g., an AI-usage-ratio dataset) is an explicit near-term goal.
2. Choose **Macro-to-Micro** when the founder's primary goal is a top-decile Roblox flagship, when a team exists, or when the market category is crowded and only a deep simulation wins.
3. Choose **Dual-Track** when the founder wants the flagship but must prove the hardest technical mechanic first (e.g., an AI-assistant NPC that actually improves learning).
4. Regardless of choice, keep the four core modules (learning interaction, regional logistics, rate formulas, full-store economy) identical — only the assembly order changes.
5. Record the chosen direction and its trigger for a switch in the architecture plan's *Build Order* section.

## Switching Triggers

* Switch **micro → macro** if Phase 1 validates the mechanic and player demand pushes toward one flagship game.
* Switch **macro → micro** if Month 3 arrives and none of the five systems is shippable; cut scope and ship the smallest module standalone.
